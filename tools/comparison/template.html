Threshold and replay settings
Shared budgetEach model learns τ from unlabeled warm-up scores, then tracks the common target α. Warm-up requests are allowed.
Individual settingsConfigure each model separately: unlabeled budget, fixed τ, validation cost tuning with that model's own costs, or an automatic validation objective.
Auto-tuneFit each model independently on held-out history using F1, F2, or balanced accuracy. The chosen τ is frozen during replay.
Validation sample
Model trainingControls the scoring model for every design. Policy tuning is a separate use of historical labels, including when the scoring model uses no labels.
Offline trainingNeural checkpoints use no fraud flags; the tree checkpoint uses its recorded historical flag count. Change it with train.py --fraud-flags N, then rebuild.
Online updateShared budget: quantile-loss update after each decision, step size 0.025 bits. Fixed, cost-tuned, and auto-tuned policies keep their fitted/configured τ frozen.
αShared budget: chosen target. Individual fitted policies show each model's validation blocking rate; fixed policies show the configured rate. Neither is a fraud probability or a future false-block guarantee.
Same-history comparisonAll transfers continue. Every model sees identical completed events and uses its own τ.
Independent blockingEach model's blocks change its own subsequent history. This compares policies under a fixed request schedule.
Blocked attemptsUpdate GRU memory where present; do not create completed-payment edges or value.
Future requestsFixed scenario schedule; does not simulate behavioral responses to blocks.
ReportsArrive later as evidence. They do not change live memory or prior decisions; supervised heads use only the offline flagged-history export.
